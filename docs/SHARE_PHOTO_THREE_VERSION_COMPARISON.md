# 情境一「分享照片」：Raw／Masked／Task-Minimal 三版本比較

執行日期：2026-11-05
資料：v5 合成資料集 576 筆 SHARE_PHOTO 任務（192 個虛構手機環境 × 3 筆）
指令：`make share-compare`（`python -m receiver.share_photo_compare`，固定 seed 20261107）
證據檔：`receiver/data/share_photo_compare/comparison.json`、`pairs.jsonl`、`manifest.json`

決賽藍圖第十二節要求對同一任務比較三個版本，用來區分「一般去識別」與「任務導向最小揭露」。情境二已有 A／B／C 對照，本文件補上情境一。

## 1. 三個版本的定義

| 版本 | 內容 | 代表什麼 |
|---|---|---|
| Raw | 任務語句、參數，加上整份手機環境：聯絡人、已安裝 App、收藏地點、使用者與裝置資料、權限、電量、網路、系統狀態、畫面、照片、訊息、通知、行事曆、定位、剪貼簿、通話、App 使用紀錄 | App 有權限就把整支手機 Context 交給 Agent |
| Masked | 與 Raw 完全相同的結構，但姓名、電話與 LINE 參照、媒體 URI、EXIF 位置、地址、畫面與通知文字、使用者與裝置 ID 以固定標籤取代，訊息文字經 `redact()` 遮蔽；不刪任何欄位，也不做任務白名單 | 一般「去識別」做法：藏值，不藏結構 |
| Task-Minimal | 政策引擎（`receiver/core_tasks.py`）實際產生的 planner packet：任務範圍 token（CONTACT_、PHOTO_、TASK_）加五個布林事實與 selection；決策不是 ALLOW 時沒有封包 | 本專案的任務導向最小揭露 |

## 2. 量測指標

每筆任務對三個版本各算：

- **欄位值數（leaves）**與**位元組數**：Agent 實際收到多少東西。
- **直接識別值數**：識別欄位（display_name、phone_ref、line_ref、media_ref、exif_location_ref、address_ref、各種 text_ref、user_id、device_id）中仍是真實值（非標籤）的個數；訊息文字只在仍含 Receiver 會拒絕的識別值時計入。
- **非任務區段數**：分享一張照片不需要、卻出現在輸出裡的區段（共 15 類：訊息、通知、行事曆、定位、畫面、App 使用紀錄等）。
- **跨任務可連結**：輸出是否帶有同一環境內穩定的 contact_id／photo_id／app_id；Task-Minimal 則算 token 在多筆任務重複出現的次數。
- **必要條件保留（保真度）**：收件人可解析、照片可解析、分享 App 狀態已知、EXIF 位置旗標仍在。

## 3. 結果

| 指標 | Raw | Masked | Task-Minimal |
|---|---:|---:|---:|
| 有輸出的任務數 | 576 | 576 | 19（只有 ALLOW） |
| 每筆輸出平均欄位值數 | 621.8 | 621.8 | 18.0 |
| 每筆輸出平均位元組 | 22,230.6 | 19,154.9 | 479.2 |
| 直接識別值總數 | 72,849 | 0 | 0 |
| 每筆輸出非任務區段數 | 15.0 | 15.0 | 0.0 |
| 跨任務可連結輸出數 | 576 | 576 | 0 |
| 必要條件保留（4 項） | 490～576／576 | 490～576／576 | 19／19（ALLOW 任務全部保留） |

決策分布：ASK 320、STOP 213、LOCAL 24、ALLOW 19。ASK／STOP／LOCAL 的任務在 Task-Minimal 下什麼都不送：缺授權、取消、收件人歧義、照片缺失、快照過期或未確認時，雲端不會收到封包。

## 4. 解讀

1. **Masked 把識別值歸零，但沒有減少揭露面**。欄位值數一個都沒少，15 類與任務無關的區段原樣送出，而且 contact_id、photo_id、app_id 讓同一支手機的多筆任務可以被串起來。這就是「去識別不等於最小揭露」。
2. **Task-Minimal 把每筆輸出從 621.8 個欄位值降到 18 個**，非任務區段為 0，token 在 576 筆任務中零重複；19 筆真正送出的封包全部保留收件人、照片、App 狀態與位置旗標四個必要條件。
3. Raw 與 Masked 的保真度不是 576／576，是因為資料集刻意放入收件人未綁定或歧義（86 筆）與照片缺失（36 筆）的任務；這些在 Task-Minimal 下會走 ASK，而不是送出不完整的封包。

## 5. 限制

- 資料是合成模板，所有識別值都是 SYN_* 佔位；數字量的是結構，不是真實重識別風險。
- 「必要條件保留」是規則定義的四個條件，不是獨立人工標註的任務成功率。
- Masked 版本的遮蔽規則是本比較自訂的固定欄位表，用來代表一般做法；不同的去識別實作會得到不同的位元組數，但「結構與區段不變、可連結」這個性質不會變。
- 19 筆 ALLOW 是 576 筆裡同時具備授權、雲端同意、非 STRICT_LOCAL、已確認且資源齊全的任務；比例低是資料集的設計，不是引擎的保守程度指標。
